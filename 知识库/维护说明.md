# 日常更新流程

## 在哪里改

在Obsidian中打开本项目的“知识库/首页”。默认近三年与最新优先，可从2026、2025、2024年或热词、梗、黑话/俚语入口查找。修改“条目”“来源”“待核线索”下的Markdown笔记；不要直接修改导出的knowledge.json、年代阅读版和网页内的数据。

- 条目上方属性用于ID、年代、语言、类型、来源ID等简短信息。
- 正文用于含义、笑点机制、漫画构思、使用场景、提示与来源支持范围。
- 来源笔记记录URL、发布日期、阅读日期、阅读方式和限制。
- 文件名与稳定ID保持一致；修改显示名称用title属性及正文标题，不随意改ID。
- 只有检索线索、尚未读到来源的材料，先记入“待核线索”。

## 页面维护入口

双击项目根目录“启动本地工作台.command”，进入[本地工作台](http://127.0.0.1:17861/)。可点击查询更新、编辑、删除至回收站及恢复；这些操作写入本Obsidian知识库。编辑历史和回收站在“私人”目录，联网查询记录在“采集收件箱”目录，均默认不发布。详见[使用说明](../docs/本地维护工作台.md)。

## 如何更新预览

Obsidian保存只会更新Markdown，不会自动导出网页、联网采集或推送GitHub。

让Codex执行“根据Obsidian笔记更新夸损有梗的知识包和预览，并校验”，或在独立Python环境安装tools/requirements.txt后，在项目目录执行：

```bash
python3 tools/build_from_obsidian.py
python3 tools/validate_package.py
```

只检查是否已经导出、而不修改文件：

```bash
python3 tools/build_from_obsidian.py --check
```

导出前会完整读取并校验笔记、来源引用和数据格式。通过后逐文件替换导出结果；这不是跨所有文件的事务。如果写入中断，重新运行导出，再运行校验。

当前导出范围是年代知识，不支持在笔记中编辑实时热度快照、媒体授权结果或个人使用事件；这些功能仍待下一阶段。

## 哪些不要放进公开内容

自己的二维码、个人作品、账号凭证和私人反馈放在项目外或明确忽略目录。“知识库/私人”不参与导出且已被Git忽略。不要把整个Obsidian库作为本项目的GitHub仓库。

GitHub同步与公开网站尚未配置，后续按[维护方案](../docs/Obsidian与GitHub维护方案.md)接入。

## 新分类与时间属性

focus_categories可选hotword、meme、slang，允许多选。recent_evidence_date用已核查的收录/讨论时间（年、年月或年月日），不填本次编辑时间冒充传播时间。正文“关注依据”说明年度入选、词典收录、社区票选还是当期报道。仅更新网页修改日期不能把旧词提到近期榜。

范围配置保存在“知识库/收集范围.json”，会导出为skill的focus.json并嵌入网页。修改收集年份后需重新导出。不要为了置顶而篡改recent_evidence_date。

## 收录先复审

先读[收录标准与复审区](归档与复审.md)。原始条目笔记包含暂缓资料；首页、索引、skill知识包和网页只展示`收录复审.json`中标为include的条目。新增、恢复或暂缓条目必须更新该文件；不能只凭词条有来源或海外热度就恢复。英文还需登记大陆传播证据。
