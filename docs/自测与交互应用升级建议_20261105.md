本轮发现并修复：

1. 服务重启后旧页面令牌失效：写请求收到403时重新握手，只重试一次；保留原编辑版本和正文；再次拒绝则停止，409编辑冲突不重试。通过受控响应回归测试核对，避免覆盖Obsidian外部修改。
2. 新查询失败时残留上一轮候选：查询开始即清空显示结果，失败时只显示本轮错误，旧记录仍可从历史中选择。

核心回归可运行：

```bash

node tools/test_workbench_client.cjs
.venv/bin/python tools/validate_package.py
.venv/bin/python tools/build_from_obsidian.py --check
```

运行HTTP测试需要本机监听端口权限。Node仅用于前端开发测试，普通用户运行现有本地工作台不需要Node服务。

## 当前结构已经具备交互基础

- 预览页：读取从Obsidian导出的知识数据，筛选、查找、查看来源和等级。
- 本地工作台：浏览器通过本机API查询RSS、编辑、删除和恢复Markdown。
- 海报工坊：风格、提示词/任务、昵称、二维码合成与PNG下载；模型图像由宿主执行或手工上传。
- Obsidian知识库：正式资料主本，个人历史、回收站与收件箱在本地；JSON与HTML是导出物。

因此后续可复用数据契约、编辑校验和恢复逻辑，再整合界面；不必先推翻底层内容结构。

## 建议的交互应用路线（原始规划）

后续进展：本地PWA基础版已实现，见[PWA使用与核查](PWA使用与核查_20261105.md)。以下保留提出方案时的状态；AI任务编排和跨设备同步仍未实现。

### 一体化工作台

把“浏览、收集、创作、作品、设置”放到同一个应用入口。选择一个梗即可带入文案和画面编辑；能选单张、信息图合集或排名表；统一显示任务状态、来源与个人品牌。保留Obsidian作为内容主本，接口是它的受控读写入口。

### AI创作流程

支持自然语言请求，例如：“找最近一周的趣味黑话，挑8条做萌宠合集，加上我的昵称和二维码。”后台拆成查询、候选筛选、文案、图像任务、品牌合成与归档；保留来源和实际执行状态。模型API若要由网站直接调用，需要服务端的模型适配、凭证管理、任务进度、取消与失败重试。当前离线海报页没有这些能力。

作品库保存实际生成文件、提示词、父条目、采用/不喜欢等真实反馈，支持按指令复用、改编、排重。编辑旧版本历史与生成作品历史是不同数据，当前只实现了前者。

### PWA与公开发布

可以逐步做成PWA，让网页有接近App的安装与使用体验；需要另外实现manifest、离线策略及相应部署要求，提出本方案时尚非可安装PWA；随后已接入本地PWA基础版，系统安装尚待验收。手机跨设备编辑还需要明确同步、账户权限和版本冲突方案，手机上的127.0.0.1不会自动连到Mac。

公开知识与样张可导出为公开网站；私人的二维码、作品、修改历史和回收站保持隔离。静态站点可展示公共内容，但在线采集、私有写入、模型任务需要独立后端或用户本地代理；不能把当前只监听本机的服务直接当作公开服务部署。

## Web3.0一词的区别

若用户指“更智能、更强交互”，上述AI交互应用/PWA路线可以实现目标。通常区块链语境的Web3强调去中心化、用户所有权和钱包等，是另一类产品架构；本项目现阶段没有必须引入链的业务要求。

参考：[MDN：PWA是什么](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/What_is_a_progressive_web_app)、[Ethereum：Web3介绍](https://ethereum.org/web3/)。这两项为概念与未来方案参考，不表示本项目已经实现。
