# 三种单张风格与信息图合集

读取`../assets/poster-studio/styles.json`。comic为反转漫画，pets为萌宠吐槽，retro为复古表情包；用户未指定时先采用comic。collection为信息图合集：默认8条、两列四行、竖版9:16；2—4条可单列，5—10条可双列，按实际条数编号，每条有完整文案与对应小漫画。超过10条拆页，不挤小字。单张默认竖版3:4；条目多时拆页，避免挤小字。品牌区在图外单独追加，不覆盖正文。

## 宿主模型执行

明确要图时，检查当前宿主可用的图像生成工具；有工具就实际调用，不只返回提示词。本次Codex可用`image_gen.imagegen`，使用宿主内置图像模型，不需要公开包保存API Key。其他宿主用其已授权的同类工具。不要在说明中虚构具体模型版本。

从风格定义取visual，结合本次标题、反转文案、动作场景生成完整提示词。要求清晰中文、原创角色、完整包袱；不画二维码、昵称或Logo。每种风格独立生成一张；合集须逐条核对编号、条数、全文与对应漫画，不将多条文案合并成一个场景。附件只作参考，除非用户要求，不复制附件的私人二维码。

`assets/poster-studio/index.html`可离线选择风格、编辑提示词、导出`meme-image-request.json`。任务带`status:not_executed`，收到任务的AI仍须实际执行生图。网页没有模型服务器、直连API或付费调用按钮；不要把导出任务写成已经生成图片。

模型失败时说明具体状态，保留提示词和任务；不使用占位图冒充成图。外部模型手工路线：复制提示词到用户已选模型，拿到实际成图后上传工坊合成。

## 成图与品牌

实际生成后检查文案、错别字、人物动作、画幅和截断。记录实际发送提示词、宿主工具名、输出文件名和检查状态；只有工具返回了具体模型名时才记录该版本。生成结果存入用户指定目录；本地私人作品默认放`outputs/`，不要自动加入公共样张。

用户需要昵称、签名或二维码时，打开品牌工坊处理；说明见[branding.md](branding.md)。二维码保持独立后处理，不能叫图像模型重画。
